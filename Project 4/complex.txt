A Comparison of Class Implementations: Complex Numbers

    The Norwegian duo of Kristen Nygaard and Ole-Johan Dahl are widely credited for the creation of the first programming language with classes: SIMULA I, released in 1964. Based on ALGOL 60, it made the pioneering jump from simple code blocks to derived multi-variable types with their own defined behaviours. Just short of a decade later, Dennis Ritchie's C language shook up the programming scene with a hands-on design ethos that exposed mechanisms of memory while being portable enough to allow cross-platform development. C had some core concepts from object-oriented programming, namely polymorphism through pointers and structs providing partial encapsulation. In 1985, Bjarne Stroustrup's experiments in adding classes to C culminated in the release of C++. C++ brought the power of SIMULA's object-oriented paradigm to the hackable and versatile C language. Sun Microsystems used C++ as their key inspiration for designing Java, an object-centric language designed to increase the portability of code and reduce possibility for corruption. Java's design philosophy, as a result, proves more restrictive and verbose in points than C++ to achieve the same goals. Python, a multi-paradigm language designed by Guido van Rossum through the 90s, includes many of the features that defined Java, but implements them differently. Python's emphasis on elegance and a lack of boilerplating creates a much less verbose language with more implied encapsulating structures. For this project, implementing a simple complex number class in C++, Java, and Python has given a surface-level exposure to how these different philosophies lead to different code with their own benefits and drawbacks.
    A key scale that exemplifies each language's differences is how modular each is. C++ embraces the very modifiable and hackable nature of C, in that it allows for even basic symbol operators to be manually overloaded. Even the operations of the primitive types can be overrode, through the use of friend functions. Friend functions can access private and protected fields of a class, so long as the original declaration allows for friends. This allows much easier extension of existing classes and enhanced modularity for writing new classes. Conversely, friend functions that modify class fields in ways that inherited functions cannot handle creates opportunity for unpredictable behaviour. Java explicitly eschews friend functions for this purpose, insisting that only methods in the same package as the class be able to access protected fields. Python allows for a lot of the same extensibility that C++ offers, but through a different paradigm. Instead of access modifiers being used to guard instance fields, methods use references to themselves to access their own instance fields. This is implemented through the first argument of a method, `self`. Python does not gate access to fields, making the concept of friend functions non-extant. Instead, some built-in functionality of the language can be overloaded through declaring special methods (or "dunder" methods, named for their double underscored names).
    Each language's approach to modularity plays into a key part of the developer experience: language verbosity. Java is oft-maligned for its litany of dot operators, curly braces, and encapsulation. However, its emphasis on disallowing weird symbols and its rigid class definition creates code that reads fairly simple. The need to call each method in respect to a class or object creates a less natural developer interaction with this numerical type that benefits from being able to use standard arithmetic operations. Because all non-primitive fields are pass by reference in Java, there are no reference or dereference operators used in its implementation, and therefore less reading complexity. C++, although very flexible in its language constructs and operators, requires the programmer to reference and dereference fields manually. The jumble of asterisks and ampersands can prove confusing at times, and can create confusion between references and pointers. Python, on the other hand, tries to minimize the amount of verbosity necessary through removing syntax symbols and inferring instructions. This can throw off those used to more verbose languages that allow for more free-form code, as it requires use of fixed whitespace guidelines and does away with braces for scoping. Fields are strongly typed, but are often interpretable in ways that can resemble type coercion. New variables are declared with no keywords, simply just by assigning a name a value. Python's language rules create less verbose, but not always cleaner code.
    In conclusion, each language's design philosophies and chosen paradigms create a different programming experience. When it comes to personal preference, I found Java to be the easiest and most outwardly comprehensible. Python was a lot more flexible than Java and required less boilerplate code and syntactic sugar than both Java and C++, but I did not always find its design intuitive or inherently legible. C++ was probably the most time-consuming, as my unfamiliarity with references and pointer handling created a lot of opportunities for access issues, but I found it the most enjoyable. C++ bends to every whim, in code that can be written however obtusely or simply I prefer, and can add on a lot of functionality that neither other language would allow. Also Brian Kernighan is really kind and fun to talk to, so that may add some bias. Each language has their own advantages and disadvantages that fit different needs and preferences.

C++ vs. C:
 - inheritance
 - encapsulation
 - polymorphism
   C does not have full classes that can have access modifiers and obscured (private) fields/logic, the most modular and instantiable unit is just a struct
   C++ creates full classes that can hide data and can properly encapsulate data
   C supports "object-like" structs but lacks most of the functionality of C++
   e.g. obj.method(args) vs function(obj, args)
 - classes are safer than structs, they are less easy to mangle and can hide private fields to prevent bad modification

Differences in implementations:
  Java:
  - restrictions on overloading
    less flexibility in interfacing with language functions, everything is a method call of an object
  - no friend functions
    Complex objects access the instance variables of the other Complex because they are defined of the same class
    If you wanted to allow non-Complex classes to permissibly access instance variables in their methods, they must be in the same package
  - everything by reference
    Everything is an object that gets passed by reference automatically. New assignments are given by reference to Objects
  - Syntactically heavy
    Because of how instance methods need to be accessed, Java necessitates a lot of syntactic sugar. Every object class requires a class declaration, and every instance method is accessed 
  C++:
  - Overloadable operators
    Achieved through writing operator methods, which overload the inherited basic operator methods
    Friend functions of built-in types allow us to override how primitive types interact with our object type
    << (bitwise lshift) gets overloaded by cout to yield an ostream, and we can create a friend of that too to extend an existing custom operator with support for our type
  - access instance methods through the scope resolution operator
  - Object classes can be declared as structs, like C

  Python:
  - Overloadable operators
    Achieved through special methods ("dunder" methods) that are called by built-in language functions to support additional types
  - No access modifiers necessary
    Instance variables are declared in the constructor and are referred to in instance methods through reference `self`
    Python does not handle functions differently from methods (member functions) and requires a reference to the object it is a member of in order to provide instance functionality.
